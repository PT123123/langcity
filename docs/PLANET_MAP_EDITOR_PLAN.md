# 星球地图可视化编辑器实施计划

## 目标

给第一次使用 Godot 的开发者一个简单的可视化工具，用鼠标选择并移动 `data/planet.json` 中的地图建筑（例如车站、便利店和房屋），调整朝向后保存。编辑结果继续由游戏现有加载流程读取，不更换地图格式。

本计划针对当前主地图「星球地图」。室内布局编辑、增加模型种类、地图生成器和一般 Godot 场景编辑不在首版范围内。

## 当前项目情况

- `data/planet.json` 是当前星球地图，含 `planet`、`world`、`spawn` 和 `objects` 等数据。
- `objects` 中每个条目以 `kind`、`x`、`y`、`rot` 等字段描述地图物件；`x/y` 是地图展开图坐标，不是普通 3D 世界坐标。
- `scripts/planet/planet_math.gd` 提供地图坐标与球面方向转换；`scripts/planet/planet_builder.gd` 构建真实岛屿地形及碰撞。
- `scripts/street/interactable.gd` 的 `Interactable.make(obj)` 根据条目创建游戏内建筑和物件。
- `scripts/street/street.gd` 的 `_place_on_planet()` 将物件投到地形并按切平面朝向放置。地形射线需等物理帧同步后才能可靠命中。
- `_tools/curate_planet.tscn`、`map_validate.tscn`、`map_fix.tscn` 是自动整备/检查工具，不提供人工拖拽编辑。
- Godot 4 的场景编辑器本身不会显示这些运行时从 JSON 生成的物件，因此首版适合做成项目内独立运行的 Godot 工具场景，而不是 Godot 编辑器插件。

## 首版范围

### 必须具备

1. 打开后显示真实星球地形和 `planet.json` 中的地图物件，视角可旋转、缩放和平移。
2. 鼠标点击选择物件；界面显示其 `kind`、坐标、朝向和对象序号，选择状态清楚可见。
3. 拖动物件到地形上的新位置。拖动结束后，更新地图坐标并将物件贴回地形。
4. 支持旋转所选物件，至少提供按固定角度步进旋转的快捷键或按钮；可选支持精确角度输入。
5. 保存时只更新内存地图中被编辑物件的坐标/朝向字段，并写回 `data/planet.json`；未知字段和其他地图数据必须保留。
6. 首次保存前创建 `data/planet.json.map-editor.bak` 备份；已有备份时不得静默覆盖。
7. 提供未保存修改提示，以及保存成功/失败反馈。
8. 启动过程不依赖导出模板或额外插件；使用项目自带的 Godot 4.4.1 可运行。

### 建议具备

- 可搜索/筛选的对象列表，至少能按 `kind` 筛选；方便精确选到车站等建筑。
- 撤销/重做本次会话中的移动和旋转。
- 坐标/朝向输入框，便于精确调整和恢复原值。
- 显示对象原有坐标，支持撤销单个对象改动。
- 针对 `door`、`window` 等有 `host` 字段的附属物件，移动宿主时按同一坐标偏移一并移动，避免门窗留在原地。

### 首版不做

- 新增或删除地图物件、复制粘贴、改词条或改建筑模型。
- 室内地图编辑、任务编辑或完整的通用关卡编辑器。
- 自动重新布局、自动运行会改坐标的 `curate_planet` / `map_fix`。
- 把编辑器做成需要安装和维护的 Godot EditorPlugin。

## 推荐实现方式

新增独立工具场景和脚本，例如：

- `_tools/map_editor.tscn`
- `_tools/map_editor.gd`

可按实现需要增加专用相机/选择辅助脚本，但尽量复用项目现有的 `PlanetMath`、`PlanetBuilder` 和 `Interactable`，不要复制建筑模型代码或另造一套坐标规则。

建议的场景启动命令：

```powershell
& .\_tools\Godot_v4.4.1-stable_win64.exe --path . res://_tools/map_editor.tscn
```

这是以游戏运行模式打开编辑工具场景，不是用 `--editor` 打开 Godot 的通用场景编辑器。

### 加载与场景构建

1. 从 `res://data/planet.json` 读取并解析完整字典；解析失败时停止编辑并显示错误，不能用空地图覆盖原文件。
2. 使用地图中的 `planet` 配置、`world` 尺寸、`PlanetMath` 和 `PlanetBuilder` 创建岛屿。
3. 等至少一个物理帧后再依照 `objects` 顺序调用 `Interactable.make(obj)` 并摆放物件，以匹配现有的地形碰撞射线时序。
4. 物件与 JSON 条目建立明确对应（首版可用数组索引）；选择和移动不能因显示排序而写错条目。
5. 编辑器相机和 UI 应避开游戏控制输入；至少提供鼠标相机操作说明和常用按键提示。

### 选取与拖动

- 点击 3D 物件选择它；面板显示稳定身份信息，例如数组序号、`kind`、`word`、`x/y`、`rot`。
- 拖动更新该物件的地图平面坐标，并使用项目球面映射将其重新贴合地形。
- 鼠标射线未命中真实地形时，不提交位置修改，也不能把物件放到海面或兜底球面上。
- 移动时保留条目其他字段（例如 `word`、`host`、`plinth`、`novis` 等）。
- 如果实现自动带动 host 附属物件，应按原坐标增量移动，而不是重新猜测 host 或重建其数据；需处理缺失 host 的情况且不能崩溃。

### 旋转

- 地图的 `rot` 是以度表示的朝向，游戏加载时转为弧度。
- 旋转更新 JSON 中对应条目的 `rot`，重建/更新显示时遵循与 `street.gd::_place_on_planet()` 一致的球面切平面朝向规则。
- 若物件原来没有 `rot`，首次旋转时新增该字段；未旋转的物件不应被批量写入默认值。

### 保存与恢复

- 保存前检查目标路径、JSON 解析状态和写入结果；失败时保留内存改动并告知用户。
- 在首次修改原文件之前建立不覆盖既有文件的备份。备份失败时取消覆盖保存并显示原因。
- 只写回编辑器修改后的坐标/朝向；保留根级配置及条目中未识别字段。
- 写入建议采用临时文件后替换原文件，避免程序中断造成半截 JSON。
- 提供「重新载入/放弃未保存更改」操作；确认后从原文件重新构建视图。
- 不自动调用会自动搬动对象的整备脚本。可提示用户保存后按需运行 `map_validate` 检查落点和阻路情况。

## 操作建议

首版至少在画面内显示一小块帮助说明，例如：

- 左键点击：选择物件
- 左键拖动：移动所选物件
- 右键拖动：旋转视角（或按相机实际绑定操作）
- `Q` / `E`：旋转物件（若实现快捷键）
- `Ctrl+Z` / `Ctrl+Y`：撤销 / 重做（建议）
- `Ctrl+S`：保存

具体按键由实现者依据 Godot 输入事件与相机控制方式确定，并在 UI 中保持准确。

## 验收标准

1. 能用上面的命令在项目根目录启动编辑器场景，不进入主菜单或普通游戏场景。
2. 真实岛屿和现有地图建筑正确显示；场景中的建筑数量与 JSON `objects` 数量对应。
3. 能选中车站，通过拖拽改变位置，并能通过旋转操作修改其朝向。
4. 保存后 `planet.json` 仍是合法 JSON；重启编辑器和游戏后，建筑出现在保存的位置/朝向。
5. `planet.json` 中除编辑目标字段外的数据语义不变；未编辑物件不会被改坐标或重排。
6. 首次保存生成备份；已有备份时不被覆盖。
7. 未命中地形、JSON 损坏、备份失败和写入失败都有清楚反馈，原文件不会被空数据或不完整内容覆盖。
8. 若支持宿主带动门窗，移动建筑后门窗随动；若首版不实现，UI/文档应清楚说明当前限制。

## 工作量评估

- **可用 MVP：约 1 个工作日。**显示真实场景、对象选取、拖动、旋转、带备份保存、基础错误处理。
- **推荐首版：约 1–2 个工作日。**再加对象列表/筛选、撤销重做、输入坐标、宿主附属物跟随、操作提示和完整手动验收。
- **更完整的关卡工具：数个工作日以上。**增加新建/删除物件、复制粘贴、碰撞/路径可视化、分层编辑、室内编辑等。

时间估算假设实现者熟悉基础 GDScript 和 Godot Control UI；主要不确定点是现有 `Interactable` 的选中碰撞/射线行为能否直接复用，以及球面地形上稳定拖动的手感，需在 MVP 中优先验证。

## 实施顺序

1. **验证最小技术路径：**新建工具场景，加载岛屿并显示少量现有物件；验证碰撞同步和鼠标射线落地。
2. **实现导航与选择：**相机绕岛观察、选取物件、对象信息面板及列表筛选。
3. **实现编辑：**拖动落点、旋转、坐标/角度输入；确保每个显示物件关联正确的 JSON 条目。
4. **实现安全保存：**差异更新、非覆盖备份、临时文件写入、错误提示、重载/放弃。
5. **实现编辑辅助：**撤销/重做、宿主门窗跟随、快捷键和操作说明。
6. **按验收标准手动走查：**至少编辑车站与一个普通建筑，保存并重启工具及游戏验证；检查备份及 JSON 差异。

## 给实现 Agent 的交付要求

- 先阅读 `scripts/street/street.gd` 的 `_place_on_planet()`、`scripts/planet/planet_math.gd`、`scripts/planet/planet_builder.gd`、`scripts/street/interactable.gd` 的 `make()`，沿用现有坐标和建筑构建逻辑。
- 不重跑 `_tools/make_planet_map.py`，不让 `curate_planet` / `map_fix` 覆盖人工摆放结果。
- 用仓库自带 Godot 可执行程序验证工具场景能启动，并按验收标准实际操作；报告未完成的标准和任何数据变更。
- 修改前后检查 `data/planet.json` 是否被编辑器启动流程意外改写；工具启动本身必须只读。
